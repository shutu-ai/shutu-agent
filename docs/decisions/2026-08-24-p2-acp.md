# P2 ACP JSON-RPC stdio 适配

日期：2026-08-24

## 决策

增加 `internal/acp` 作为独立的 automation-only ACP JSON-RPC NDJSON 服务，并由 `pa --acp` 暴露。ACP stdout 只输出协议帧，诊断继续写 stderr。

当前协议面包括：

- `initialize` 与 `authenticate`；
- `session/new`、`session/prompt`、`session/cancel`；
- `session/update` 中的已提交文本 `agent_message_chunk`；
- 对权限请求、图片、音频、嵌入上下文、额外目录和 MCP server 明确返回不支持。

## 运行时边界

通用 `internal/acp.Server` 按 ACP 连接维护 session，并以接口隔离协议与业务运行时。现有 `cmd/sta` 的 loop/app 状态仍是进程级全局串行状态，因此 `pa --acp` 的 factory 只接受一个新 session，并要求其绝对 `cwd` 等于 ACP 进程工作目录。这样不会把“全局当前 session”错误地宣称为多 session 隔离。

提示执行结束后，adapter 从本轮新增事件中提取 `assistant/message` 的文本，再发出 committed `agent_message_chunk`；工具调用、推理、原始增量和非文本内容不进入 ACP wire。取消通过独立 context 取消当前 turn，断开时等待已接收请求并关闭 session。

## 延后项

若需要多 session、独立 workspace、流式 token 输出、图片附件、permission bridge 或完整 SDK 类型兼容，应先把 app runtime 重构为 session-owned runtime，再扩展 adapter；本阶段不通过共享全局状态模拟这些能力。
