# P2 LSP 第四阶段决策

## 范围

实现一个只读模型工具 `lsp`，对齐 dsh 的四个精确代码导航操作：

- `goToDefinition`
- `findReferences`
- `goToImplementation`
- `hover`

## 实现

- `internal/lsp` 通过 stdio JSON-RPC 连接用户配置的语言服务器；不引入第三方协议依赖。
- 查询使用当前 session 持久化的 cwd；文件路径必须位于该 workspace 内。
- 模型侧位置是一基 UTF-16；发送给 LSP 时转换为零基位置。
- `findReferences` 额外查询 definition 并去重，以保持“包含声明”的工具语义。
- 响应有文档大小、位置数量和结果字符数上限；子进程使用无 shell 启动并清理 credential-shaped 环境变量。
- capability 默认关闭，只有 `lsp.enabled: true` 且配置 `lsp.command` 后才注册工具。

## 边界

本阶段不实现编辑器插件、长期 server pool、workspace/configuration 转发、增量同步或代码修改类 LSP 操作。每次工具调用执行一次 initialize/open/query/shutdown 生命周期，保持资源边界清晰；后续若需要性能优化，再单独引入按 workspace 复用的 provider。

## 验收

覆盖路径越界、响应解析和真实 stdio JSON-RPC 生命周期；并运行 `go vet ./...`、`go test ./...`、`go build ./...`。
